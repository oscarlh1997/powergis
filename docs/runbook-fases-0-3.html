Cimientos Fase 0

El VPS desde cero hasta un motor que responde por HTTPS. Nada de datos todavía.

01

Contratar el KVM2 con Ubuntu 24.04 LTS

Sin panel de control preinstalado: el stack va en Docker y un panel sólo compite por la RAM que necesita PostgreSQL.

Comprobación ssh root@IP entra y free -g muestra 7 u 8 GB.
02

Cerrar la máquina antes de poner nada dentro

Usuario sin privilegios, clave pública, contraseña y root desactivados por SSH.

# como root, una sola vez
$ adduser powergis && usermod -aG sudo,docker powergis
$ rsync --archive --chown=powergis:powergis ~/.ssh /home/powergis

# /etc/ssh/sshd_config
$ sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/;
         s/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
$ systemctl restart ssh

$ ufw default deny incoming && ufw allow OpenSSH
$ ufw allow 80,443/tcp && ufw --force enable
$ apt install -y fail2ban unattended-upgrades
$ dpkg-reconfigure -plow unattended-upgrades
No te encierres fuera Abre una segunda sesión SSH y comprueba que entras como powergis antes de cerrar la primera. Si la clave no está bien copiada, esa primera sesión es la única forma de arreglarlo.
Comprobación ufw status lista 22, 80 y 443, y nada más. PostgreSQL y Redis nunca publican puerto.
03

Swap de 2 GB

Con 8 GB y PostgreSQL dentro, el swap es el seguro que evita que el OOM killer se lleve la base de datos, que es el peor final posible. swappiness bajo para que se use sólo en apuros.

$ fallocate -l 2G /swapfile && chmod 600 /swapfile
$ mkswap /swapfile && swapon /swapfile
$ echo '/swapfile none swap sw 0 0' >> /etc/fstab
$ sysctl -w vm.swappiness=10
$ echo 'vm.swappiness=10' > /etc/sysctl.d/99-powergis.conf
Comprobación swapon --show muestra 2G y free -h lo refleja.
04

Docker y DNS

Traefik pide el certificado por desafío HTTP, así que el DNS tiene que resolver antes de levantar el stack o Let's Encrypt te limita los reintentos.

$ curl -fsSL https://get.docker.com | sh

# En tu proveedor de DNS, registro A:
#   motor.powergis.es  →  IP del VPS
$ dig +short motor.powergis.es
Comprobación dig devuelve la IP del VPS y docker run --rm hello-world funciona.
05

Repositorio y secretos

Los secretos viven en .env en el VPS y en wp-config.php en WordPress. En ningún otro sitio: ni en git, ni en la tabla options de WordPress.

$ git clone … powergis && cd powergis
$ cp .env.example .env

# genera cada secreto, no los inventes
$ openssl rand -hex 32   # HMAC_SECRET      (el mismo en wp-config.php)
$ openssl rand -hex 32   # INTERNAL_API_KEY
$ openssl rand -hex 24   # POSTGRES_PASSWORD
Nunca en producción POWERGIS_DEV_MODE activa el simulador de pago. Si acaba definido en el WordPress de producción, cualquiera desbloquea informes de pago gratis. No lo definas ahí jamás.
Comprobación make check-config pasa sin avisos. Se niega a dar por buena una configuración con DEBUG, secretos cortos o ENV mal puesto.
06

Levantar el stack

Por defecto arranca la configuración de KVM2. El perfil de teselas queda apagado: GeoLens es fase 5 y no tiene sentido gastar memoria antes de tiempo.

$ make up
$ make ps
Comprobación curl https://motor.powergis.es/health responde 200 con certificado válido. En make ps los ocho servicios están healthy o running.

Demografía del INE Fase 2

La parte que convierte el sistema en un producto: el almacén con datos reales. Es también donde un fallo silencioso hace más daño.

09

Verificar el mapeo antes de cargar nada

El INE renumera tablas al republicar una operación, y los filtros del colector son subcadenas del nombre de la serie. Los dos fallan sin lanzar ningún error: simplemente devuelven cero hechos.

$ make ine-verify
VeredictoQué ha pasadoQué hacer
OKLa tabla responde y el filtro aciertaSeguir
UNREACHABLEEl INE renumeró la tablaBuscar el ID nuevo y fijarlo por entorno
NO_MATCHCambió el nombre de las seriesAjustar match con lo que muestra el ejemplo
LEVEL_MISMATCHLa tabla ya no es municipalCambiar el nivel del TableSpec
EMPTYLa tabla existe pero está vacíaRevisar en la web del INE

Para arreglar un ID sin tocar código ni desplegar, mira la tabla y fíjala por variable de entorno:

$ make shell
$ powergis ine-discover 56934      # qué variables y series tiene

# en .env, y luego  make up  para recargar
INE_TABLE_DEM_POP_TOTAL=59525
Comprobación El comando termina con «Las 16 tablas del INE responden y mapean» y código de salida 0.
10

Cargar el Padrón

Va a la cola etl, con su propio worker y concurrencia 1, para que una carga larga no deje esperando el informe de un cliente. Medido: una ingesta de 282 s bloqueando slots compartidos retrasa informes.

$ make ingest-ine        # verifica primero y aborta si no cuadra
$ make derive            # densidades, ratios, índices
Tarda Son varias tablas municipales completas con límite de 2 peticiones por segundo al INE. Déjalo correr y sigue los logs con make logs.
Comprobación En make psql: SELECT count(*) FROM fact_indicator; en millones, y SELECT count(*) FROM fact_indicator WHERE value IS NULL; debe ser una minoría. Un montón de nulos significa que el filtro no acertó.

15

Backups, y restaurar uno

Los snapshots del VPS no son copia de seguridad de base de datos. Y una copia que nunca se ha restaurado no es una copia: es una carpeta.

$ make backup
$ make restore-test
Comprobación restore-test levanta la copia en una base temporal y cuenta geografías y hechos. Si los números cuadran, el backup sirve.

Vigilancia y salto a KVM4 Después

Cuándo hace falta más máquina, medido en vez de intuido.

→

Un solo comando para decidirlo

$ make capacity

Muestra memoria y CPU por contenedor, la profundidad de cada cola y las conexiones abiertas contra el máximo de PostgreSQL. Las señales para migrar:

  • PostgreSQL sostenido por encima del 85 % de su techo.
  • Cola reports.* con espera habitual en hora punta.
  • La carga nocturna del INE sin terminar antes de las 07:00.

La migración conserva los volúmenes, así que no hay que recargar el almacén:

$ make backup
$ make down
# redimensionar en el panel de Hostinger
$ make up TIER=kvm4
Comprobación make capacity con los techos nuevos y make smoke en verde después del salto.

El formulario no hay que tocarlo

[crear_proyecto_v6] envía el payload completo —definición, ticket, buyer persona, ecosistema y entorno— y el conector lo traduce entero. Lo único que faltaba era el código INE: los desplegables de ubicación mandan el nombre («Comunidad de Madrid»), y scope.ine_code es obligatorio en el motor, así que hoy toda creación se rechazaría en el borde. Es el TODO anotado en rest-projects.php, y la respuesta es que no, el árbol no manda código.

Se resuelve en class-geo-resolver.php, contra el padrón del motor y siempre dentro de la provincia —en España hay decenas de municipios homónimos y resolver «Madrid» a ciegas devuelve datos de otra zona sin dar ningún error. Verificado: el payload real del formulario entra en el motor y produce 12 criterios de Match %.
